Beyond sight.

Publish for every reader.

SightPress is a powerful multi-site, multi-language CMS for everyone, designed with blind and low-vision content creators and audiences who use assistive technology in mind.

Accessibility is the floor, good design is the goal, and neither is ever traded for the other. Test releases are out for developers and testers now; version 1.0 will be the first for live websites.

The basics

What is a CMS?

A CMS, or content management system, is the tool you use to create, edit and publish a website without writing code.

You write pages, add images and organise menus in an admin area. The CMS stores that content and turns it into the web pages your readers see. WordPress is the best-known example.

Why another one?

Most content tools are built for the mouse and the eye first. SightPress is built so that its admin area works as well with a screen reader or a keyboard as with a mouse, and so that what you publish works for every reader.

Progress

Where we are

SightPress is released in small test versions while we build towards 1.0. Each one is tested with a keyboard and a screen reader before it ships.

Released so far

  • 0.5.0, 27 November 2026: Modules from other developers, your own roles, sign-up limited to your organisation, optional text messages and three new blocks.
  • 0.4.0, 24 November 2026: Themes you can choose per site, captions and transcripts, large and resumable uploads, and optional cloud storage.
  • 0.3.0, 19 November 2026: Private analytics with charts you can read in words and tables, and an optional AI assistant that only suggests.
  • 0.2.0, 19 November 2026: Languages and translations, site search, members-only pages, older versions, scheduling and redirects.
  • 0.1.0, 17 November 2026: The first usable version: build pages from blocks, publish checks, the admin panel and several sites in one installation.

What’s next

  • Being built now, 0.6.0: Getting ready for 1.0: a security review, tools to download or delete your personal data, and faster pages.
  • Before 1.0: a security review, privacy tools, speed, complete documentation and an independent accessibility review.
  • 1.0: the first version for live websites.

Get involved

Help us build it

You don’t need to write code to help. Here is where each kind of help makes the most difference.

  • Try a test release

    For developers and testers. Install SightPress on your own computer with Docker and tell us what breaks. Test releases aren’t ready for live websites.

    Getting started guide

  • Report a barrier or an error

    Accessibility barriers are always treated as bugs. Tell us what you tried, what happened and which assistive technology you use, by email or on GitHub.

    How to report a problem

  • Test with assistive technology, or translate

    If you use a screen reader, a magnifier, a braille display or voice control, or you speak another language well, we’d love your help.

    Email contribute@sightpress.org

  • Follow the development

    SightPress is built in the open. Read the code and follow our progress on GitHub, or follow the blog in your feed reader.
