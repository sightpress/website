Available in 0.4.0

Available now

Everything in this section works in test release 0.4.0. Each item links to a step-by-step guide in the documentation.

Writing and publishing

  • Build pages from ten kinds of block: heading, text, image, gallery, video, audio, file download, columns, call to action and contact form. Write and publish a page
  • Pages move from draft through review to published, and can be published or taken down at a set time. Schedule a page
  • Compare any older version word by word, with changes written out as “removed” and “added”, and restore it without publishing it. Restore an older version
  • Copy, archive, trash and move pages, with redirects that keep old addresses working. Move or rename a page
  • Menus, and an audit log of who changed what.

Accessible by default

  • An admin panel designed to be used with a keyboard and a screen reader: upload progress is announced, and the menu shows only what your role can use.
  • Checks before publishing: image descriptions, link text, captions, transcripts and heading order. An accessibility error stops a page from being published until it is fixed.
  • Images need a description, or an explicit choice to mark them as decorative.
  • Each new site starts with ready-made pages, including an accessibility statement. Create a website

Several sites and languages

  • One installation runs several websites, each with its own people, pages and files.
  • Each page can have a translation in any available language, with its own title, address and content. Translations start as drafts. Add a language
  • Search engines are told which pages are translations of each other, and each language has its own sitemap.
  • The admin panel, site texts and emails are in UK English, European Portuguese and Spanish. Translate SightPress

People and sign-in

  • Invite people, or let them create their own account. Let people sign up
  • Make single pages, or a whole site, readable only by signed-in members; those pages stay out of search engines. Make a site members-only
  • Password resets, invitations and new accounts use a six-digit code that you type on a page, never a link in an email. Codes we send you

Search, analytics and the AI assistant

  • Site search on every page, with no outside service. It ignores capitals and accents, and marks matches in bold and underlined, not only in colour. Search your website
  • Private analytics on your own server, with no cookies and no IP addresses stored. Every chart has a summary in words and the same data in a table. See who visits your website
  • An optional AI assistant, off for new sites, using your own key. It drafts and suggests; a person always decides, and AI-written alt text and translations must be checked before publishing. Use the AI assistant
  • A title, description and structured data for every page, a sitemap, and a Markdown version of each public page for AI tools. Each site decides how AI crawlers may use its content.

Themes and design

  • Choose a theme for each site and preview it first. Themes are installed on the server, never uploaded through the website. Install and change a theme
  • Change a theme’s colours for light and dark mode. A colour that would be too hard to read is refused, and the message names the colours that clash.
  • Home, standard, landing, sidebar and full-width page layouts, each becoming a single column on a narrow screen. Choose a page layout
  • Developers can start their own theme from the theme template, with checks and a tutorial. Create a theme

Media

  • Captions for videos in each of your site’s languages, and transcripts for videos and recordings. A page with a video or recording can’t be published without them. Add captions and transcripts
  • Large files upload in parts, with progress announced to screen readers. Pause, resume or cancel, and carry on for up to a day if the connection drops. Upload large files
  • Upload limits for each site, and imports of very large files from the server. Import files from a folder
  • Optional cloud storage, such as AWS S3 or Cloudflare R2, with a content delivery network; unpublished and members-only files stay protected. Keep files in the cloud

Running SightPress

  • Runs with Docker, on MariaDB, MySQL, PostgreSQL or SQLite, with FrankenPHP, nginx or Apache. Getting started
  • Turn optional features on or off for each site; turning one off keeps its data. Turn features on or off
  • A command line tool for tasks such as creating a website. Try the command line tool
  • Update to a newer version, keeping every website. Update SightPress

Every change is listed in the 0.4.0 release notes.

In progress

Being built now: 0.5.0

The next release is about extending SightPress and setting rules for who can join a site.

  • Add-on modules from other developers, installed with Composer and turned on or off for each site, with a module template and a step-by-step tutorial.
  • Custom roles, so each organisation can decide exactly who may do what.
  • Rules for which email addresses and domains may join a site.
  • Optional text messages: notifications, signing in with your phone number, and a second confirmation for important changes. Text messages are off unless a site sets them up.

Plans for a release that isn’t out yet can still change.

Planned

Before 1.0

Version 1.0 is the first version for live websites. Before it, we make SightPress safe, private, fast and fully documented.

  • Security: a full security review of the code, and checks that personal data never appears in error messages or logs.
  • Privacy: tools to meet UK and EU data protection law, so people can download their data or delete their account, and site owners can choose how long data is kept, with a generated privacy policy and cookie list.
  • Speed: page caching and performance budgets.
  • Running it for real: guides for running SightPress on a public server, on one server or several, and an upgrade tool.
  • Documentation: a guide or reference for every feature, command and setting.
  • Accessibility: an independent review, including blind and low-vision users, and a published accessibility conformance report.

Planned

After 1.0

After 1.0, SightPress grows with the people who use it. These are plans, and they may change.

More help with accessible content

  • A link checker that finds broken links and links to documents that don’t say their type and size.
  • Checks on uploaded PDFs, and a readability score for each language.
  • Display preferences for visitors (text size, spacing, contrast and motion), without an overlay.
  • An accessible form builder and an accessible audio and video player.

Moving from WordPress

The first module after 1.0 imports a WordPress site into SightPress.

Official modules

  • For every site: news with feeds, events, a documents library, newsletters, and maps with text directions first.
  • For charities: donations with Gift Aid, volunteers and membership plans.
  • For public bodies: meetings and minutes, consultations, transparency data and emergency alerts.
  • For small businesses: catalogues, bookings and job vacancies.
  • For individuals: podcasts with transcripts, portfolios and CVs.

Further ahead

In time, SightPress could go beyond websites: events, bookings, courses and an online shop, then tools to run a small organisation, such as contacts, help desk and invoicing. Each would meet the same accessibility standard as the CMS.
